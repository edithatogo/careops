# Product definition

CareOps is an organisation-neutral source and delivery control plane for independently deployable administrative and clinical-governance capabilities. It progressively integrates the family's reusable source into this repository while preserving each module's authority, runtime, tests, licence/provenance and deployment contract.

## Current source and work selection

Read [the source registry](../portfolio/repos.json) and [module catalog](../portfolio/module-catalog.md) before selecting work. The checkout contains both ordinary integrated source and exact-pinned optional submodules. A historical migration receipt or a catalogued proposal must not be mistaken for the current source form or an installed service.

Use [the existing suite queue](suite-delivery.md) and [track registry](tracks.md); reconcile current ownership and open work before creating a new track or moving a module. Source consolidation does not imply shared operational storage, automatic interoperability or native activation.

## Product boundaries

- Reuse existing Microsoft 365 and Power Platform capabilities and qualified access routes; tool availability does not establish permission.
- Keep confidential tenant, clinical, personnel and operational data, credentials and private acceptance evidence outside source control, regardless of repository visibility.
- Preserve accountable human decisions, existing records and native write holds. Approval to develop is not approval to deploy, grant access, publish or send email.
- Deliver a usable bounded core before optional analytics, discovery and cross-module integrations. The planned SharePoint Catalogue follows its own standard-capability-only scope; it does not require CKAN, bespoke SPFx or premium/Copilot services.
- Distinguish source tests, runtime qualification, tenant commissioning and operational acceptance. Never infer one from another.

[Agent instructions](../AGENTS.md) and [development standards](../docs/development-and-delivery.md) govern execution. This product definition does not change security policy, source pins, business ownership or deployment permissions.
