## Findings and applied fixes

1. **High — incomplete PubMed source shape.** Retained `Xml.Document` metadata is a list of named elements. The initial adapter required an object. Changed to accept list roots, preserve exact Bronze list and carry an explicit Silver `xml_nodes` representation, with a regression case.
2. **High — generic JSON paths hide XML semantics.** A `Value[]` path conflates grants, authorship, abstracts and corrections. Added XML-aware semantic element/attribute paths, repeated occurrence counts and private ordered source-field occurrences; original XML tree remains authoritative.
3. **Medium — false 100% field usage.** Empty data previously satisfied vacuous all-used status. Now an empty input is not complete utilisation, and mapped vs retained/excluded/unassessed fields are explicitly separate.
4. **Medium — source identity or count drift.** Rollup now rejects profiles not matching the exact registered source name, duplicates, missing data and count reconciliation failures.
5. **Medium — redundant full-record JSON serialisation.** Removed repeated whole-object encoding from profiling; retains bounded traversal and nonfinite numeric checks.
6. **High — source coverage vs business utilisation.** Historical source model has 20 physical register fields but Europe PMC 140 populated paths, OpenAlex 232 and Semantic Scholar 45, with accepted 1,344-publication native scope. These are not additive or necessarily complete provider dictionaries. Field profiling alone is not downstream utilisation. Registered source-by-source native adoption tasks.
7. **High — current accepted private source access not established.** No claim that 1,277 accepted PubMed records or full source/consumer parity were analysed by new code. Accepted private receipts, current source owner, rights and model/version readback must precede production measurement.

### Source implementation and tests
- `portfolio-scripts/rims_utilisation_opportunities.py` consumes the existing 17-source catalogue and accepted field-profile/utilisation **shapes**, rather than raw provider values. It emits a ranked review task for every unassessed observed field, with source/domain/path, type and missingness context.
- Declared consumer mappings are reported separately from verified analytical usage. An absent private profile is **not** treated as 100% coverage, and an empty profile has no numeric usage rate.
- Review found that field types could contain arbitrary strings from an untrusted profile and appear in a metadata report. **Fixed:** only the known null/boolean/integer/number/string/array/object vocabulary can be surfaced. Metadata paths and field names may themselves be sensitive; real reports stay in the authorised private environment.
- Local TDD evidence: initially 6 focused tests passed; the new field-type security test failed before the fix; **7 synthetic tests passed after the fix** on Python 3.13.5. This does not qualify the exact GitHub PR HEAD under canonical Python 3.15.1 or prove native bindings.
- Existing 136 source tasks and 23 T18 indicators remain owned by their current tracks; this additive prioritiser creates no replacement source inventory or new collectors.
