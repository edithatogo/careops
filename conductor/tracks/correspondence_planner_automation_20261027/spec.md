# Automatic correspondence tasks and completion reflection

Status: source and stopped native preparation verified27October2026; runtime unverified, activation held. This is a feature of the existing correspondence solution, not a new correspondence register.

## Requirements

1. Create one Basic Planner task automatically only for a reviewed, open correspondence entry with an explicit human Action required decision and approved short action title. Do not classify mail or opt in existing records.
2. Reuse the existing stable list/item action key, ETag claim, task ID/URL, reciprocal links and uncertain-create/partial-save recovery. Preserve the manual linked-action flow and its owner/run-only permissions. Manual and automatic writers share the same identity protocol.
3. Reflect qualified Planner task state/completion time into technical log fields. Preserve human notes, task edits, correspondence Progress, review state, due dates and source links. Never automatically close or reopen correspondence.
4. Show completed actions with open correspondence in Ready for closure review. A person checks the whole matter and explicitly edits the existing Progress field. Task completion is insufficient proof that the whole correspondence is finished.
5. Treat unavailable, deleted, mismatched, stale and incompletely scanned tasks as exceptions. Preserve history and human edits; do not create a replacement task blindly.
6. Reuse Standard Planner/SharePoint connections, Basic plan, technical receipts and CMO/EDMS pages. Protect waiting-too-long calculations from sync changes to Modified; retain unknown waiting dates explicitly.
7. Prepare a proposed15-minute, single-worker route Stopped. Validate local source, exact native save/readback, bounded fictional runtime/recovery, role journeys and separately authorised prospective pilot in sequence.
