# Implementation plan

Complete packets in order through the first fictional approval slice (01–04). Each packet names its owner, output and completion evidence. Monitoring can proceed independently once the event contract is stable.

- [ ] **01 · Workforce evidence map.** In the authorised work mailbox, scope searches to junior medical recruitment and commencement. Review matched conversations and privately record request class, actor role, requested evidence, decision, exception and hand-off. With the user's DocuSign sign-in in the internal browser, compare the matching template roles and routing order with envelope history where needed. Keep recruitment enquiries, application updates and observership separate from commencement. Mark each rule observed, proposed or unresolved. Deliver a de-identified routing matrix with evidence coverage and outstanding policy questions. An observed signature sequence alone cannot establish delegation authority.
- [ ] **02 · Process map.** In CareOps Process, map engagement, request, revision, stage and optional envelope reference to its existing object/event contract. Record submitted, assigned, returned, revised, decided and closed events and their producers. Walk a fictional request through the map. Send missing authority or evidence questions to the coordinator's exception queue in the design.
- [ ] **03 · Approve configuration.** Inspect the pinned module's existing request, routing and audit contracts. Add the smallest onboarding request profile and synthetic fixtures. Require engagement key, site, role, start date, requestor, revision and evidence references. Configure effective-dated site/role rules with accountable manager, permitted substitute, delegate requirement and rule version. Missing, expired, conflicting or self-approval routes require review. Derive assignees server-side. Snapshot the route at submission.
- [ ] **04 · First deliverable in Approve.** Implement manager decision first. On approval either complete the sign-off or open the required delegate stage. A return requests a new revision. A rejection closes that revision. Keep cancellation, expiry and technical failure distinct. Claim a unique request/revision/stage key before creating an approval. Persist the provider reference, verify responder authority and use a conditional write on the active revision. Reconcile uncertain creation before retry. Ignore stale responses for current status while retaining audit history. Exercise manager-only, conditional delegate and returned/resubmitted paths through the local entry point with a fake approval provider. Include duplicate submission and late response in those traces. Record decisions and expected final states with delivery disabled.
- [ ] **05 · Workforce workbench.** Use SharePoint Lists for restricted requests, revisions, stages, routing rules and task projections. Specify unique keys, lookup indexes, conditional updates and role-scoped list access. Use a versioned evidence library with restricted links and document type/revision metadata. Keep signed evidence in its authoritative location. Build Power Apps intake, review, correction and coordinator exception screens using the same Approve transition contract. Surface the app in Teams. Confirm the proposed access matrix against fictional coordinator, requester and approver scenarios before native use.
- [ ] **06 · Monitoring in Process.** Project only a stable event ID, pseudonymous object keys, revision, stage, event type, time and outcome. Deduplicate on event ID. Define Power BI open-stage count, age since assignment, submission-to-final-decision duration and proportion of requests returned. Count distinct request revisions for backlog and distinct requests for return rate. Replay the fictional traces twice and reconcile counts with Approve. Monitoring failure must leave decisions recoverable in Approve.
- [ ] **07 · Solution packaging and handoff.** Inventory the existing CareOps Approve solution source before adding components. Keep the app and solution-aware Power Automate orchestration together. Declare environment variables and connection references for SharePoint and Approvals. Package list/library provisioning separately and keep real bindings private. Use installed PAC help to select local solution pack/unpack commands, retain one round-trip component comparison, and produce a settings template and dev-to-managed-release instructions. List licensing, connector policy, target permissions, external signature handling and rollback prerequisites for the deployment owner. Keep email delivery off. Native import, activation, flow execution and operational acceptance are separate future decisions.

## Handoff receipt

For each packet record the owning module, commit, changed files, targeted check and residual gap. Reuse earlier receipts when inputs are unchanged. Suite integration follows module qualification and exact pin review. An approvals prototype is usable for local review after packet 04 even while the workbench and monitoring remain open.
