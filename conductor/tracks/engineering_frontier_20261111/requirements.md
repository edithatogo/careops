# Engineering frontier requirements (MoSCoW)

All MUST items require demonstrated executable acceptance rather than documentation assertions. `source`, `CI`, `package`, `native` and `production` qualifications are different evidence levels. Every capability has a valid AI-off and premium-off mode.

| ID | Priority | Requirement | Acceptance evidence |
| --- | --- | --- | --- |
| EF-R01 | MUST | Existing protected checks, hash-pinned tools and action policies are never bypassed for ordinary merge; billing/unexecuted jobs are never reported as tested failures or passes | Exact PR-head and merged-main status/classification receipts; #301 closed only after actually executed checks |
| EF-R02 | MUST | A deterministic task packet identifies owner/module, allowed paths, prerequisites, test selection, evidence and forbidden effects | Versioned schema, valid/invalid fixture tests, no implied authority from text |
| EF-R03 | MUST | Context retrieval is bounded, source-revision-aware, relevant to changed paths and excludes private source/evidence | Golden task cases: required context present, stale/wrong module rejected, no classified data in packet |
| EF-R04 | MUST | Enforce tool permissions outside model instructions; read/plan/test default and explicit, narrowly scoped write/merge/deploy boundary | Adversarial tool-chain tests for injection, path traversal, credential leakage, scope creep and network egress; default denial |
| EF-R05 | MUST | Fail-closed orchestration with recoverable checkpoints, immutable task/source IDs, no duplicate writes, bounded retries and timeouts | Deterministic fault, crash/retry, cancellation, replay and concurrent-writer tests |
| EF-R06 | MUST | One repository-owned offline entrypoint discovers eligible module tasks, selects minimal checks and preserves full release gates | Fresh-checkout synthetic build and fault tests; no ambient credential/authentication or paid service requirement |
| EF-R07 | MUST | Security and privacy tests run on changed source and relevant history, with explicit reviewed-finding policy and no raw sensitive logging | True-positive, false-positive, encoded/archived document, binary and bypass fixtures; actionable non-sensitive receipts |
| EF-R08 | MUST | Dependency, source and package integrity use exact pins, locks, licence/provenance review, SBOM and verified release digests | Clean rebuild and altered-file negative tests; attestations where actually available; no unsupported private-repo signing claim |
| EF-R09 | MUST | Critical integration boundaries use schemas, version compatibility, identity, idempotency, failure/recovery and authorization tests | Producer/consumer fixtures, expired/stale/replayed/duplicate and absent-optional-provider cases |
| EF-R10 | MUST | Native Power Platform artefacts are built/packed/tested from authored source with preserved bindings and independently verified target identity before any enabled operation | Offline pack/unpack parity plus separately scoped native readback, duplicate-write/refusal/rollback tests |
| EF-R11 | MUST | Core licensing manifest detects mandatory premium connector, custom connector, Copilot or unsupported Dataverse dependency | Known-standard passes; injected premium/unknown connector fails; optional module remains installable alone |
| EF-R12 | MUST | Agent/model use never controls credentials, approvals or release gates and is never mandatory for deterministic workflows | AI-disabled full core test, malicious retrieval/prompt/tool fixture, approval spoofing refusal |
| EF-R13 | MUST | Each claimed technical capability has a reproducible exact-input benchmark or regression and explicit NOT-QUALIFIED states | Immutable manifest of tool/runtime/source/fixture versions and actual execution/results; zero fabricated success |
| EF-R14 | SHOULD | Add property/stateful, mutation, metamorphic, fuzz and differential testing where defect models justify them | Representative mutants discovered, test quality score and reproducible seeds; avoid blanket gates on low-risk files |
| EF-R15 | SHOULD | Detect architectural/context drift across integrated modules, pinned optional modules, docs and contracts | Automatic changed-path impact graph, stale instruction/owners/pins, missing test target negative fixtures |
| EF-R16 | SHOULD | Self-repair suggestions are restricted to disposable branches with independent tests and source review | Red/green test attached, patch preview, no agent-owned protected merge or native mutation |
| EF-R17 | SHOULD | Capture minimal useful CI and agent-execution metrics to optimise throughput and resource use | Tool calls, wall time, selection precision, reproducibility, flaky failures and prevented unsafe actions; no sensitive text |
| EF-R18 | SHOULD | Performance, failure injection and resource limits protect sync/replay/analytics workloads | Bounded representative synthetic benchmark; response, memory and concurrency baselines at pinned revisions |
| EF-R19 | COULD | Support independent local agents and provider adapters behind identical permission/context contracts | Local-provider, remote-provider and no-model parity fixtures without privileged dependencies |
| EF-R20 | COULD | Add dependency-aware differential test selection and automatic patch suggestions | Baseline vs incremental comparison; selection false negatives are release blockers |
| EF-R21 | WON'T | Build a new always-on orchestration service, mandatory external vector store, mandatory paid AI, duplicate policy engine or shadow business database | Scope control |
| EF-R22 | WON'T | Claim clinical/administrative effectiveness, publish private operational data, activate tenants or retire existing systems as part of this technical source track | Separate operational authority |
