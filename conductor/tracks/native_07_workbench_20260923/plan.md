# N07 plan: one usable workbench

Owner: Product and accessibility owner, to be named. All tasks planned.

- [ ] N07.02 Define role-purpose access views with profession/facility/own-record constraints; accept user-approved minimum information without broad inferred access.
- [ ] N07.03 Build register search/filter and scope detail; accept clear conditions, supervision, valid dates, last-recorded state and source currentness.
- [ ] N07.04 Build one case view showing changes, outstanding items and evidence links; accept review in context without duplicate entry or agent-check approval.
- [ ] N07.05 Build restricted delegation/profile editing with before/after view; accept visible effective dates, source instrument and independent approval status.
- [ ] N07.06 Implement text/icon equivalents for RAG and unavailable states; accept keyboard, screen-reader, contrast, zoom and mobile task tests.
- [ ] N07.07 Provide approved external-practitioner/referee access if required; accept least-privilege identity, licensing and privacy tests before exposing any portal.
- [ ] N07.08 Test deep links/API/export and SharePoint links outside the UI; accept authorisation independent of hidden controls and revoked-session handling.
- [ ] N07.09 Test slow/interrupted rural connectivity and downtime warnings; accept no cached stale view silently presented as current approval.
- [ ] N07.10 Run representative task-based acceptance with each user group; accept reduced net work, accessible guidance and named support before pilot.

Screens cannot create authority. A user's professional background does not by
itself entitle them to confidential documents or broad register access.
