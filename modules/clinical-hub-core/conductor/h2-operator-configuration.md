## Ordinary operator experience: smallest proposed extension

Reuse the existing library/forms and preparation route. This is a conditional
design, not a selected schema mutation, new app, list, register or runtime.
Inventory any subsequently selected existing occurrence record before deciding
its mapping; no such record's controls are assumed to exist from a name alone.

1. Open the existing preparation location and select a maker-maintained forum
   option with a readable name. Duplicate labels must be disambiguated; display
   text must never be used as identity. If no qualified option exists, retain
   manual preparation and record the missing mapping.
2. Select one occurrence, displaying date, local timezone, exception/cancellation
   and profile revision. Keep original occurrence identity separate from a moved
   date. No guessing by subject or silently selecting the latest profile revision.
3. Review the effective period and supported preparation controls. Select only
   maintained role/evidence, source/version and template/version options applicable
   to that forum and occurrence. Unverified, draft and conflicting evidence stays
   visible and cannot become an approval. Show no issue/send capability.
4. Review a readable summary of forum, occurrence, selected revisions, sources,
   destination and outstanding holds. Missing choices, stale options, ambiguity,
   cancelled preparation or changed source require reconciliation, not fallback
   to another forum or a favourable default.
5. Only a separately qualified maker-owned bridge may derive the immutable
   selection snapshot/digest and existing adapter arguments. No such native
   bridge is built or invoked in H2.3b. Operator input is never native authority.
6. Continue the existing maintained Word/manual preparation and review route.
   Document preparation does not approve or distribute content. Save any future
   qualified draft under its own revision, preserving edits and issued history.
