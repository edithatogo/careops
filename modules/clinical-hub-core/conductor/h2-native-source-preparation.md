## Future exact-target preparation checklist: not authority to execute

Use this only when the relevant native work is separately selected. Retain one
writer and the existing native/file owner; never infer rights from CLI login,
metadata access, a connector name or a fictional passing test.

1. **Select the narrow change.** Resolve the applicable H1 governance and H2-U/H2-R
   dependencies for that operation. Identify an existing exact target and a small
   permitted diff. Do not manufacture a multi-forum graph, duplicate flows/registers
   or create an app to bypass an unsupported control. Keep the maintained fallback.
2. **Qualify access and state.** Through the retained workload's guarded exact GET
   route, capture current identity/environment, complete definition, full connection
   references, state and relevant version/ETag. Qualify actual owner/edit rights,
   applicable schema permission, connection compatibility and terminal runs; a
   creator field is not a complete owner inventory. Do not inspect unrelated
   people's workflows/access. A running/On target or in-flight owner operation
   holds this preparation; no authority to stop it is granted here.
3. **Retain a complete private preimage.** Record source commit/helper/fixture and
   target mapping versions; raw response bytes/hash; full graph/parameters/manual
   schema; complete existing connection-reference identities; state/owners and
   version/concurrency evidence. Retain any affected existing field definitions,
   content-type/form settings and source/template/output lineage separately.
   Dated earlier captures must be refreshed before a selected native write.
4. **Generate only the supported candidate.** Use the existing entry point and
   exact bindings. Pin both full preimage and candidate; enumerate added/changed/
   removed paths and schema/choice/default effects. Preserve target identity,
   references, existing guards, legacy/manual branches and permitted Stopped state.
   A missing bridge or unqualified mapping stays a blocker, never a placeholder
   inserted into a live flow. Do not send a full management response blindly as
   an update: server-managed properties are not a write payload.
5. **Preflight effects and the exact operation.** Qualify the supported existing
   same-client save route, permitted payload, target permission, concurrency guard
   and prospective private journal. Bound transport to one mutation attempt and
   no automatic retry/redirect. Check notification effects, including service
   failure alerts/account digest, before any later fictional runtime case. Do not
   enable/suppress settings, run a probe or deliberately fail a flow in this task.
6. **Independently read back only after an authorised save.** Compare the complete
   intended graph/manual schema, parameters, full references, target and state,
   retaining actual raw bytes and any narrowly qualified service normalisation.
   Existing `flow_definition.definition` is a pure comparison helper, not a general
   normaliser or a replacement for full non-definition identity/reference checks.
   Unknown authentication/reference/schema shapes must be investigated, not erased
   or patched around. Native save success still does not prove output or runtime.
