# Build and publication rules

Current source home: `edithatogo/careops`, `modules/clinical-hub-core`.
See [migration and continuity](MIGRATION.md). This supersedes older child-repository development directions below.

Build one usable meeting capability at a time. Technical completion means saved
configuration, expected output and relevant conflict/recovery behaviour. Do not
require real meeting participation, measured organisational outcomes or business
approval to complete software setup. Reuse passed checks and standing authority;
record each material result once. Avoid duplicate evidence packs and status polling.

Power Platform/Microsoft 365 is the operational runtime. Use local code for source,
template preparation and testing only. Keep one agenda/pack, one minutes record,
one authoritative action register and one preparation route; link existing papers.

Use existing individual permissions and actually held administrator rights only.
No Entra administration, new app registration, service identity, consent or spending
is implied. Reuse qualified CLI sessions; verify only the affected target. Do not
repeat general licence questions. An optional blocked connector holds that feature
only. Password/MFA and materially new access/distribution decisions remain human.

This repository is PUBLIC. Never add real meetings, transcripts, operational
registers, tenant identifiers, account details, private journals or binary evidence.
Use fictional fixtures and placeholder bindings. Gitleaks does not detect all
confidential material; review text as well as secrets. Never merge old private Git
history. Preserve private originals outside this repository.

Use the qualified Python baseline from .python-version and hash-locked dependencies;
evaluate newer development runtimes in isolation before promotion. Run affected
tests for routine edits; use make ci audit for dependency/runtime changes. Existing
native object ownership stays with its implementation lane. No tenant action follows
from importing this source. Prefer the Codex internal browser; use BrowserOS Neo when that route cannot support the selected operation. Preserve qualified VS Code workload/account/tenant authentication.

## Canonical workspace and private continuity

This is the canonical Clinical Hub development repository. Do not resume source
development in the archived predecessor. The private `.private-workspace/` link
contains the preserved operational plans, native journals, historical source and
uncommitted working files. It is excluded from Git; do not stage its contents,
private/ evidence, deployment bindings or binary artefacts. Use its existing
Conductor plans and private/ops records for native state. New reusable code and
fictional tests belong here. Historical native helpers remain private until their
exact-binding behaviour can be qualified independently; never deploy fictional
public binding constants into an existing flow. No Git history is imported.

The selected native document route is SharePoint library columns and maintained
Word templates, with manual narrative editing where refresh is not proved.
Document generation, metadata changes and test success do not authorise sending,
issuing or publishing records. No email may be sent or automatic delivery enabled
without the human user's explicit approval of recipients, content, attachments and
send scope. General implementation authority and historical approvals do not count.
Keep unapproved delivery Off or fail-closed and never send a test email.

Use the exact .python-version runtime through an explicitly selected repo-local
interpreter; ambient python3 or an old virtual environment is not version proof.
Qualify newest dependencies and maintained development candidates in isolation;
update runtime pins, hash locks, CI and documented commands together. Preserve
running environments until their operations finish.
