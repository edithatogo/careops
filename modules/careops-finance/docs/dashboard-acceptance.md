# Dashboard Acceptance and Publish Readiness

This document is the working checklist for the two standalone dashboards. It stays in a no-deploy posture until the dashboards are validated and the publish blockers are cleared.

## Common Readiness Gate

- [ ] `./scripts/Invoke-Validation.ps1 -Mode SourceControlReady` passes locally and in CI.
- [ ] No raw Access databases, extracts, or credential files are tracked in git.
- [ ] Deployment profiles stay disabled in both dashboard manifests.
- [ ] Validation notes are completed for both dashboards.
- [ ] Publish blockers are recorded with an owner and next action.
- [ ] Dry-run deployment remains pending until workspace and authentication details are confirmed.
- [ ] Live TMDL and PBIR exports for each dashboard pass `./scripts/Invoke-Validation.ps1 -Mode SourceControlReady`.
- [ ] Local-proof PBIR bindings are refreshed with `./scripts/Set-PbirLocalProofBindings.ps1` after regenerating report JSON, so checked-in visuals target fields present in the Access-backed TMDL exports.
- [ ] Generated PBIR pages and generated visual IDs pass `tests/pbir/Test-PbirReportStructure.ps1` against each dashboard `report-implementation-spec.md`, with structured coverage warnings recorded for missing or extra page and visual IDs while partial PBIR generation is still in progress.
- [ ] Published refresh remains blocked until `./scripts/Invoke-Validation.ps1 -Mode PublishRefreshReady` passes with externally supplied SQL Server and gateway details.
- [ ] pbi-cli and pbi-tools verification output is recorded before publish approval.
- [ ] Private GitHub remote expectation is confirmed as `private` -> `git@github.com:<org>/careops-finance.git`, with no push from the handoff pass.
- [ ] Deployment dry-run checklist in `docs/Deployment/dry-run-checklist.md` is complete before any `pbi-tools deploy ... true` command is run.

## Readiness Modes

| Mode | What it proves | What it does not prove |
| --- | --- | --- |
| `RepositoryHygiene` | The repository has valid scripts, required readiness docs, disabled deployment profiles, ignored raw data, and no tracked forbidden source files. | It does not require live TMDL/PBIR exports. |
| `SourceControlReady` | The repository is ready to carry the interim TMDL/PBIR exports in source control, with PBIR JSON parse checks and no requirement for SQL Server host details. | It does not prove published refresh can run. |
| `PublishRefreshReady` | Source-control readiness plus real Dataset source files and operator-provided `PBI_SQL_SERVER_HOST`, `PBI_SQL_DATABASE`, `PBI_GATEWAY_ID`, `PBI_TENANT_ID`, `PBI_CLIENT_ID`, and `PBI_CLIENT_SECRET`. | It should not pass while the database name, gateway path, or credentials are unknown. |

Treat the current interim target as `SourceControlReady`: TMDL/PBIR exports may be valid and reviewable while SQL Server publish-refresh remains blocked.

Local proof should open the checked-in `.pbip` packages with the sibling `Dataset` folders and embedded sample partitions generated by `scripts/Set-PbirEmbeddedSampleData.ps1`. This allows report inspection without opening Access or reaching SQL Server. The SQL Server host/listener for the later published refresh path is `<sql-server-host>`; database, schema, gateway, workspace, and credentials remain external inputs.

Use the Power BI CLI surface first for report work: `pbi report`, `pbi visual`, PBIR JSON, TMDL folders, and `pbi-tools` validation/deployment dry runs. Treat Power BI Desktop UI as an inspection fallback, not as the primary build or validation mechanism.

CI runs `RepositoryHygiene` and `SourceControlReady` with `-SkipPowerBiCli`. `PublishRefreshReady` is a protected operator gate only; it requires the environment values above plus confirmed workspace and approval details.

## Acceptance Evidence Template Generator

Generate reviewer-facing evidence templates from the checked-in acceptance packs without connecting to SQL Server, opening Power BI Desktop, or mutating dashboard source artifacts.

Markdown to stdout:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\New-AcceptanceEvidenceTemplate.ps1 -Dashboard Both -Format Markdown
```

JSON to stdout for automation:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\New-AcceptanceEvidenceTemplate.ps1 -Dashboard Both -Format Json
```

Optional file output writes only the requested template file. Prefer ignored local evidence folders such as `data/profile/vmo-acceptance/` or `data/profile/medical-staff-acceptance/` for filled evidence, and do not commit source extracts or credentials.

Use the generated template to capture sample-result checks first, then PBIR/TMDL structure checks, and leave SQL-dependent items open until the live host and gateway are confirmed.

Schema validation:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\acceptance\Test-AcceptanceEvidenceTemplate.ps1
```

## Required Docs And Hygiene Checks

- `docs/powerbi-alm.md` explains the no-deploy posture and the dry-run gate.
- `conductor/tracks/dashboard-acceptance-and-publish-readiness/plan.md` tracks the work items for this readiness pass.
- `scripts/Invoke-Validation.ps1 -Mode RepositoryHygiene` checks required docs, deployment profile state, and tracked source-control hygiene.
- `scripts/Invoke-Validation.ps1 -Mode SourceControlReady` also requires live TMDL and PBIR report exports, plus PBIR structure/coverage checks, without requiring SQL Server host or gateway details.
- `tests/pbir/Test-PbirReportStructure.ps1` validates generated PBIR page order, page dimensions, visual JSON, and exact generated visual IDs where they are present in the report implementation specs, while reporting missing or extra coverage as structured warnings instead of blocking unfinished generation work.
- `scripts/Invoke-Validation.ps1 -Mode PublishRefreshReady` requires the source-control gate, pbi-tools Dataset source files, and externally supplied publish-refresh environment values.
- `docs/Deployment/dry-run-checklist.md` records the no-deploy dry-run sequence.
- `docs/Deployment/powerbi-alm.env.sample` lists the non-secret names of required operator environment variables.
- Keep `*.accdb`, `*.laccdb`, `*.pbix`, `*.pbit`, and `*.pbip.bak` out of git.
- Keep `data/raw/`, `data/extracts/`, and `data/profile/` out of git.
