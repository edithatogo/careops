# Credentialing next implementation backlog

This backlog is ordered to preserve a small, reversible MVP while preparing for later capability packs.

## Now: understand and measure

1. Complete the CHHHS read-only current-system discovery checklist.
2. Confirm current local policy, delegations, committee authority and records boundaries.
3. Walk through one routine renewal in Cairns Services and one in Rural and Remote Services.
4. Establish baseline time, touches, rework, expiry exceptions, staff burden and practitioner experience.
5. Confirm whether a supported API, export or read-only view exists before using HTML extraction.

## Next: silent routine-renewal evaluation

1. Configure a minimum-necessary source adapter in a non-production environment.
2. Reconcile source observations through a human review queue.
3. Run retrospective and prospective silent comparisons.
4. Evaluate completeness, mismatches, false alerts, missed exceptions and time released.
5. Keep the existing system and decision process authoritative.

## Then: committee and decision support

1. Add structured committee readiness, quorum and conflict checks.
2. Assemble source-linked papers and exception summaries.
3. Record committee recommendation separately from delegated decision.
4. Draft correspondence for human review.
5. Retain immutable references and privacy-minimised process events.

## Later capability packs

- Rural Generalist Medicine core and selected advanced-skill modules;
- facility and service capability overlays;
- mutual recognition and changed-scope pathways;
- interim, emergency and disaster pathways;
- conditions and supervision monitoring;
- review and appeal;
- aggregate assurance reporting;
- approved register and release-to-practise integration; and
- controlled safety-signal references.

## Features to evaluate, not assume

- AI Builder or equivalent document extraction;
- Power Apps human-review workbench;
- Dataverse and Power Platform MCP in read-only development contexts;
- Power Automate Process Mining compared with CareOps Process;
- Copilot Studio event-triggered reminders and exception digests;
- private or local models for bounded OCR, extraction and comparison; and
- GitHub Copilot agents for source-controlled development and testing.

Each feature requires a simpler comparator, information classification, provenance, human fallback, measurable benefit, support model, rollback and a separate production decision where applicable.
