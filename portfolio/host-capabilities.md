# Source hosting and deployment authority

The public repository carries reviewed reusable source and synthetic fixtures.
Deployment authority and enterprise destinations are supplied through private
profiles. Publishing this source does not migrate enterprise repositories,
tenant configuration, operational records or decision authority.

The replacement starts with a fresh Git history. Earlier repository history,
issues, reviews, logs, artifacts and local business-document preparation are
retained in a private recovery archive, outside this repository. Historical
completion claims remain bounded by their recorded source or runtime scope.

Public CI validates source contracts, planning, fictional simulations and the
publication boundary. The cross-module compatibility workflow remains available
for manual execution using an explicitly configured integration credential with
access to the pinned private modules. Until that route is qualified, cross-module
runtime, tenant access and operational acceptance remain pending. A skipped
integration workflow is not proof of compatibility.

Issue synchronization defaults to the public source repository. Enterprise
sync requires an explicit untracked targets file; never publish its account
mapping or credentials. No issue synchronization runs as part of publication.

Security settings and hosted checks must be confirmed on the replacement
repository. Source checks do not establish native Power Platform operation or
production approval. Existing deployed resources and module owners retain their
assignments.
